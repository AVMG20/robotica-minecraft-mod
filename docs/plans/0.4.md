# 0.4 plan: tool and weapon modules, wireless charging, quarry tiers, demolish, polish

Three streams in separate worktrees, then a merge, a final audit, fixes and the 0.4.0 release.
Read `docs/AGENT_BRIEF.md` (rules) and `docs/DESIGN.md` first. Work alone (no subagents), keep tool calls short.

Shared-file rules (all streams):
- `docs/DESIGN.md`, `src/main/resources/assets/robotica/codex/chapters.json`: edit only the sections/chapters of your
  own modules. Codex text stays very short (bullets, one or two numbers); the `codexFitsTheBook` test must pass.
- `scripts/data/codex_guide.py`: add/move unlocks for your own new recipes; re-run it.
- Wiki: update the hand-written sources for your items (`scripts/wiki/items/*.json`, `scripts/wiki/upgrades.json`,
  `scripts/wiki/guides/*.md`; format in `scripts/wiki/FORMAT.txt`) and run `python3 scripts/wiki/build_wiki.py` to
  check for warnings, but do NOT commit the generated `docs/wiki/` output (it is rebuilt after the merge).
- Tests: `scripts/docker-build.sh runGameTestServer` (Docker, no local JDK) and `python3 scripts/audit_assets.py`.
- Commit on your branch, plain imperative subject, no `Co-Authored-By`, no tool advertising, do not push.
- Balance: in line with Mekanism/Thermal-style packs; ours may be a bit better or worse. Every number in config.

## A. Tool and weapon modules (module `gear`)

One module system to learn: the Tinker's Bench fits modules into power tools AND FE weapons, the same way the Exo
armor has module items with levels and a minimum tier.
- Bench: accept FE tools and FE weapons; module slots per tier (e.g. Mk/Age of the tool: 1 / 2 / 3 / 4); refuse with a
  reason (wrong tool type, tier too low, already installed). Existing Auto-Pickup and Void Filter cards keep working
  (migrate them into the new system or keep them as modules). G screen toggles every installed module.
- Drill modules: Torch Placer (places torches from your inventory where it is dark after mining). Ore-Only,
  Seismic Ping (the Exo Sonar Pulse covers it) and Magnet (auto-pickup covers it) were dropped by the user.
- Weapon modules: Armor Pierce (part of damage ignores armor; levels), Chain Lightning (Arc Blade only: more arcs /
  jumps), Ricochet Rivets (Rivet Gun only: rivets bounce to a second / third target), Lifesteal (Age 4 only, Null Lance
  and top-tier weapons; heals a small share of damage dealt, paid in FE, hard cap per second and a cooldown so it
  never makes you unkillable).
- Polish in `gear`: sounds/particles for the new modules, HUD hints, tooltips that list installed modules.
- Tests: bench install rules, torch placer, ricochet target count, lifesteal cap and FE cost, migration of old cards.

## B. Wireless charging and quarry tiers (modules `power`, `automation`)

- Wireless Charger (power): a block that charges the FE items of players in range (worn Exo armor first, then held
  items, then the rest of the inventory). Owner/team only (config to allow everyone). Range and rate scale with tiers
  or range/speed cards; feeds from cables or a Tesla coil link like any machine. Visible: a soft arc or particles to
  players being charged, a sound, a GUI with players in range and FE/t.
- Excavator and Survey Rig Mk2-Mk4: upgrade in place (right-click the placed machine with the next Mk, contents,
  energy and progress kept), each Mk faster and one more upgrade slot (like industry and processing), higher card caps.
  Read the current Survey Rig (it was just reworked into a place-once random ore generator) and Excavator code and make
  the Mk steps meaningful for each (e.g. Excavator: bigger base area, faster; Survey Rig: rate, and rarer ores at higher
  Mk if that fits its design).
- Polish in `power` and `automation`: working animations or glow while running, consistent sounds, side config where
  an item machine still lacks it, Jade info.
- Tests: charger priority, range and owner rules, FE accounting; Mk upgrade keeps contents; Mk stats.

## C. Architect demolish mode and polish elsewhere (module `architect` + others)

- Demolish (Architect Table): a mode that clears the whole grid again: every built plot's footprint and height,
  including everything inside (furniture, chests, other blocks). Two-step confirm in the GUI. Robotica building blocks
  go back as matter (config refund share), other blocks break with their drops, container contents are kept; all of it
  goes into a container touching the table, else on top of it (same rules as clear terrain: junk voided by tag, never
  the table itself, unbreakable blocks skipped, claims/spawn protection respected). Runs over time with progress like a
  build, faster than building. The plan is empty afterwards. Tests: demolish clears blocks, keeps chest contents,
  refunds matter, skips the table and protected blocks.
- Polish everywhere else (not `gear`, `power`, `automation`, `exo`): `industry`, `processing`, `energy`, `storage`,
  `logistics`, `replicator`, `drones`, `warp`, `architect`: every Mk'd machine can be upgraded in place by right-click
  with the next Mk (processing currently only via crafting), side config on every item machine that lacks it, a visible
  working state (animated/glowing texture, particles) and consistent work sounds, Jade info. Keep it consistent with
  the existing code style; small, safe changes.
